# Этап 5. Тестирование — отчёт

Дата: 2026-10-26 · Тестировщик: Claude · Инструменты: Node 22 + fake-indexeddb + Playwright (Chromium)

## Виды тестирования

### 1. Модульные тесты (tests/run-tests.js) — 18/18 ✅
Правила и операции на настоящей реализации IndexedDB (fake-indexeddb), без интерфейса:
- валидация всех вводов (R11), серия 🔥 на 4 сценариях дней (R4), знаки истории;
- регрессии критичных багов ревью: обёртка конфигурации, счётчик PIN, знак снятия отметки, снимки цен корзины;
- отказные сценарии: минус невозможен (отметка, списание, покупка), отметки только за сегодня, assignToday без запроса/без задач, дубль запроса;
- идемпотентность ensureToday (отметки не теряются), сброс базы.

### 2. Интерфейсные E2E (tests/e2e.mjs) — 16/16 ✅
Реальный Chromium, экран iPhone 390×844, живой IndexedDB, сценарий «семья за неделю»:
онбординг → перезагрузка → неверный/верный PIN → 2 задачи → товар → выход → запрос подростка → «Назначить на сегодня» → 2 отметки (20 ⭐) → корзина ×2 → возврат штуки → перезагрузка (персистентность) → «Выдано» с подтверждением → «Выдано» в истории → тёмная тема.

### 3. Что НЕ прогонялось (честно)
- Реальный iPhone (установка, свайпы, камера) — этап 6, после деплоя.
- Нагрузочное/многопользовательское — вне MVP (одно устройство).

## Найденные ошибки

**В приложении: 0.** Все падения прогонов дали ошибки в самих тестах:
1. Подмена сигнатуры API (waitForFunction в Playwright: `(fn, arg, options)`, а не как в Puppeteer).
2. Тест ждал «2 из 2» — а счётчик честно показывает «выполнено 0 из 2».
3. Тест дважды кликал ПЕРВУЮ кнопку (page.click берёт первую): отметил задачу и тут же снял её.
4. Тест ждал «×1» — приложение показывает «×N» только при двух и более штуках (по дизайну).

Это нормальная часть тестирования: тесты — тоже код, у них свои баги. Приложение выдержало.

## Вывод

16 критериев приёмки из спеки ревизии 4, проверяемых без телефона, — выполнены. Этап 5 пройден, можно отдавать код на контрольное ревью Кодексу, затем — этап 6 (деплой + iPhone).
